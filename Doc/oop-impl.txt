# Generic-function dispatch implementation

Idle implements Common Lisp-shaped `defgeneric` and `defmethod` forms using
fixed fields in Wasm GC class descriptors. Dispatch is single dispatch on the
first argument and takes constant time; it never searches an ancestor chain at
runtime.

This document follows the linked-list declarations in `benchmark/oop-list.idle`:

```lisp
(defclass List)
(defclass Nil (List))
(defclass Node (List)
  (next $List))

(defgeneric $tail ((list $List) $List))

(defmethod $tail ((list $List) $List)
  $list)

(defmethod $tail ((list $Node) $List)
  (classes:get Node next $list))
```

## 1. One Wasm signature per generic

The generic declaration creates the function type shared by its dispatcher,
fallback, and every method implementation:

```wat
(type $generic.tail.sig
  (func
    (param $list (ref $List))
    (result (ref $List))))
```

Every generic has at least its explicit receiver parameter and exactly one
result. A method may narrow only the first parameter to a subclass. Its other
parameter types and result must match exactly, so all implementations remain
valid references of this one Wasm function type.

## 2. Stable descriptor slot

The generic is introduced on its declared dispatch class. The class descriptor
gets a function-reference field at a stable offset:

```wat
(type $List.tag
  (sub $tag
    (struct
      (field $classes.parent-tag (ref null $tag))
      (field $generic.tail (ref $generic.tail.sig)))))
```

Every subclass descriptor repeats the inherited field prefix. A generic whose
dispatch class is lower in the hierarchy adds its slot only there and below.
This is the same prefix-layout rule used for instance fields.

## 3. Method ABI

Method source parameters are explicit:

```lisp
(defmethod $tail ((list $Node) $List)
  (classes:get Node next $list))
```

The implementation itself uses the generic's base receiver type so it can be
stored in the shared slot. It casts that hidden ABI receiver once and then runs
the body with the source parameter name and specialized type:

```wat
(func $generic.tail.Node.impl
  (type $generic.tail.sig)
  (param $generic.receiver (ref $List))
  (result (ref $List))
  (local $list (ref $Node))

  (local.set $list
    (ref.cast (ref $Node)
      (local.get $generic.receiver)))

  (struct.get $Node $next
    (local.get $list)))
```

There is no implicit `$this`. Different methods may choose different parameter
names without changing their shared ABI.

## 4. Compile-time method selection

Class descriptors contain the method already selected for that class:

```wat
(global $List.tag.value
  (ref $List.tag)
  (struct.new $List.tag
    (ref.null $tag)
    (ref.func $generic.tail.List.impl)))

(global $Nil.tag.value
  (ref $Nil.tag)
  (struct.new $Nil.tag
    (global.get $List.tag.value)
    (ref.func $generic.tail.List.impl)))

(global $Node.tag.value
  (ref $Node.tag)
  (struct.new $Node.tag
    (global.get $List.tag.value)
    (ref.func $generic.tail.Node.impl)))
```

`Nil` has no local `$tail` method, so its descriptor inherits the nearest
ancestor implementation. `Node` replaces the slot with its specialization.
This resolution happens once while the compiler constructs descriptor values.

For a generic or hierarchy branch with no applicable method, the slot contains
a generated function of the correct signature whose body is `unreachable`:

```wat
(func $generic.tail.fallback
  (type $generic.tail.sig)
  (param $list (ref $List))
  (result (ref $List))
  (unreachable))
```

That makes empty and partial generics structurally valid without adding a
runtime lookup or applicability protocol.

## 5. Public dispatcher and call syntax

Calls use the ordinary function syntax:

```lisp
($tail $cursor)
```

The public function has the generic's source name. It loads the receiver's tag,
loads the fixed slot, and tail-calls the selected reference:

```wat
(func $tail
  (param $list (ref $List))
  (result (ref $List))
  (return_call_ref $generic.tail.sig
    (local.get $list)
    (struct.get $List.tag $generic.tail
      (struct.get $List $tag
        (local.get $list)))))
```

A call from `defun` lowers like any other named direct call:

```wat
(local.set $cursor
  (call $tail
    (local.get $cursor)))
```

The indirect operation remains inside `$tail`. Its runtime work is two fixed
field loads and one `return_call_ref`.

## 6. `call-next-method`

Within a method, the compiler precomputes the nearest strict ancestor class
that locally defines the same generic. A source call:

```lisp
(call-next-method $object $new-value)
```

is lowered directly to that implementation with the complete supplied argument
list:

```wat
(call $generic.write.Counter.impl
  (local.get $object)
  (local.get $new-value))
```

Arguments are always required, including the receiver, and their count must
equal the generic arity. The values replace the current method arguments. There
is intentionally no redispatch and no applicability-preservation check. If no
ancestor method exists, the statically selected target is the generic fallback.

## 7. Runtime cost

For `($tail $cursor)`, the generated path is:

```text
direct call $tail
  -> load cursor.tag
  -> load tag.$generic.tail at a fixed offset
  -> return_call_ref selected implementation
```

The Wasm engine may optimize the indirect site with its own inline cache. Idle
does not maintain a language-level cache, method table, or ancestor search.
